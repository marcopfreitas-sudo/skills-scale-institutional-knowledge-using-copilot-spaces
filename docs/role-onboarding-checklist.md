# Role Onboarding Checklist

## Purpose
This checklist accelerates team member onboarding by providing role-specific orientation guidance, key resources, and success criteria.

## General Onboarding (All Roles)

### Week 1: Getting Started
- [ ] Access GitHub repository and project board
- [ ] Join team Slack channels and communication tools
- [ ] Review [OctoAcme Project Management Overview](./octoacme-project-management-overview.md)
- [ ] Review [OctoAcme Roles & Personas](./octoacme-roles-and-personas.md)
- [ ] Schedule 1:1 introductions with team lead and key collaborators
- [ ] Review current project charter and roadmap
- [ ] Understand team's Definition of Done and quality standards
- [ ] Set up local development environment (if applicable)

### Week 2: Deep Dive
- [ ] Attend first team standup
- [ ] Review past retrospectives and understand current improvement initiatives
- [ ] Understand risk register and current blockers
- [ ] Review recent releases and incident reports
- [ ] Attend sprint planning and understand backlog prioritization
- [ ] Meet with direct reports or key collaborators (1:1 or group)

### Week 3-4: Active Participation
- [ ] Participate in sprint ceremonies
- [ ] Complete any role-specific training or certifications
- [ ] Take on first task or responsibility
- [ ] Provide feedback on onboarding experience
- [ ] Review and refine understanding of cross-functional interactions

## Developer Onboarding

### Before Start Date
- [ ] Laptop and development environment configured
- [ ] GitHub access granted
- [ ] Repository cloned and build verified locally
- [ ] Code review tool access (if applicable)

### Week 1
- [ ] Review team's coding standards and best practices
- [ ] Review system architecture overview
- [ ] Complete code review of recent PRs (observation)
- [ ] Review testing standards and test coverage expectations
- [ ] Review CI/CD pipeline and deployment process
- [ ] Set up code editor and development tools
- [ ] Understand Definition of Done for code changes

### Week 2
- [ ] Submit first PR for review
- [ ] Participate in code review as reviewer
- [ ] Understand team's approach to technical debt and refactoring
- [ ] Learn incident response process and on-call rotation
- [ ] Review security guidelines and compliance requirements

### Week 3-4
- [ ] Complete first story independently
- [ ] Participate in design review or architecture discussion
- [ ] Demonstrate understanding of testing strategy
- [ ] Contribute to retrospective discussion

### Success Criteria
- Can successfully build, test, and deploy code locally
- Submitted and merged at least one PR
- Understands system architecture and component interactions
- Complies with coding standards and quality practices
- Actively participates in team ceremonies

## Product Manager Onboarding

### Before Start Date
- [ ] Review market analysis and competitive landscape
- [ ] Review customer feedback and usage data
- [ ] Understand business model and revenue streams
- [ ] Review past product roadmap and decisions

### Week 1
- [ ] Review product vision and strategy
- [ ] Analyze current user metrics and success metrics
- [ ] Interview key customers or user groups
- [ ] Review user research and feedback channels
- [ ] Understand pricing and packaging strategy
- [ ] Review go-to-market strategy

### Week 2
- [ ] Attend product roadmap review
- [ ] Review current backlog and prioritization rationale
- [ ] Understand key user personas and their needs
- [ ] Review competitive differentiation and positioning
- [ ] Understand sales and support feedback mechanisms

### Week 3-4
- [ ] Define or refine success metrics for current projects
- [ ] Prioritize backlog items based on strategy
- [ ] Prepare for roadmap planning session
- [ ] Contribute to sprint planning and feature definition

### Success Criteria
- Understands product vision, strategy, and market position
- Can articulate key user personas and their needs
- Actively prioritizes backlog based on business value
- Defines clear success metrics for features
- Collaborates effectively with engineering and stakeholders

- [ ] Update project documentation and artifacts

## QA Lead Onboarding

### Before Start Date
- [ ] Review current testing strategy and test coverage
- [ ] Understand quality metrics and defect tracking
- [ ] Review automation framework and tools
- [ ] Understand product features and known issues

### Week 1
- [ ] Review quality standards and Definition of Done
- [ ] Understand current test coverage and automation ratio
- [ ] Review defect tracking process and severity levels
- [ ] Understand test environment setup and data management
- [ ] Review regression test suite and manual testing approach
- [ ] Understand release readiness criteria

### Week 2
- [ ] Conduct quality audit of current work-in-progress
- [ ] Review test automation strategy and gaps
- [ ] Understand critical user journeys and test scenarios
- [ ] Develop test plan for current sprint/milestone
- [ ] Identify quality improvement opportunities

### Week 3-4
- [ ] Lead test planning for first feature or release
- [ ] Establish quality metrics and dashboards
- [ ] Mentor QA team member on testing approach
- [ ] Perform first acceptance testing

### Success Criteria
- Understands quality standards and Definition of Done
- Can assess test coverage and automation gaps
- Develops and executes comprehensive test plans
- Establishes quality metrics and visibility
- Collaborates with development on quality improvement

## Scrum Master Onboarding

### Before Start Date
- [ ] Review team composition and current dynamics
- [ ] Understand sprint schedule and ceremonies
- [ ] Review team's velocity and burndown trends
- [ ] Understand current blockers and impediments

### Week 1
- [ ] Meet with each team member individually
- [ ] Attend first standup and observe team dynamics
- [ ] Review sprint backlog and work-in-progress
- [ ] Understand team's Definition of Done
- [ ] Identify current blockers and impediments
- [ ] Review recent retrospective outcomes and action items

### Week 2
- [ ] Facilitate first standup as Scrum Master
- [ ] Conduct first retrospective
- [ ] Identify team health and engagement issues
- [ ] Support removal of identified blockers
- [ ] Review metrics (velocity, cycle time, burndown)

### Week 3-4
- [ ] Facilitate sprint planning and refinement
- [ ] Mentor team on Agile practices and continuous improvement
- [ ] Track action items from retrospectives
- [ ] Provide coaching on team dynamics and collaboration

### Success Criteria
- Facilitates effective ceremonies with good participation
- Identifies and helps remove team blockers
- Tracks action items and drives continuous improvement
- Coaches team on Agile practices
- Maintains high team engagement and psychological safety

- Integrates security into development lifecycle
- Establishes security compliance and metrics
